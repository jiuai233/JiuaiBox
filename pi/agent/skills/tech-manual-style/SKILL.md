# Tech Manual Style

这套设计语言来自 Pi Durable 技术手册（190 页，用 HTML + Paged.js 排版）。整体气质是**老式工程图册加上现代开发者文档**：暖色纸底、蓝黑墨色、细线、等宽大写标签、图版式插图，没有一处纯装饰。

它好看的根本原因是**每个视觉元素都有含义、有出处，而且全书保持一致**：颜色有语义，箭头有语法，图注先说结论，每节都列出来源。动手之前先理解这一点，这比照抄色值重要。

## 文件

| 文件 | 内容 | 何时读 |
|---|---|---|
| `assets/tokens.css` | 全部设计 token：字体、字号、间距、中性色、10 种语义色（基色 / 线色 / 填充色）、深色模式 | 每次都用 |
| `assets/components.css` | 组件类（前缀 `tm-`），见下方组件表 | 每次都用 |
| `assets/specimen.html` | 完整样张：封面、部分扉页、小节、图表、表格、要点框 | 起手模板，照着拼 |
| `references/figures.md` | 图表语法：节点、8 种箭头、步骤号、时间线、放大镜标注，以及 SVG 起手代码 | **画任何图之前必读** |
| `references/print.md` | Paged.js 打印 / PDF：@page、页眉页脚、页码交叉引用、印刷字号 | 要做 PDF 或印刷品时 |

## 怎么用

1. **单文件 artifact 或网页**：把 `tokens.css` 和 `components.css` 的内容内联进 `<style>`，`<body class="tm">`，加上 tokens.css 顶部注释里的 Google Fonts 链接。用 `assets/specimen.html` 的结构起手。
2. **已有项目（React / Tailwind 等）**：把 `tokens.css` 当作全局变量引入，组件按这里的规则用项目自己的组件重写，不要硬套 `tm-` 类。Tailwind 可以在 `theme.extend.colors` 里引用 `var(--aqua)` 这些变量。
3. **只要配色或字体**：只用 tokens.css，但**语义色规则仍然适用**。
4. 中文内容加 `lang="zh-CN"`。字体栈已经回退到苹方 / 宋体，components.css 会给中文收紧字距、关掉伪斜体。

## 五条原则（以及为什么）

1. **颜色就是含义。** 每种颜色在整份文档里只代表一类东西，读者学一次就能读懂所有图。开写之前先确定颜色表，放进文档前言的“图中的颜色”一节。**rose 只用于失败**（崩溃、中止、错误）；如果拿 rose 做装饰，读者就再也分不清哪里出了问题。
2. **四种字体，各管一件事。** 读者凭字体就能分辨自己在看什么：
   - Manrope：标题、Logo。字距收紧 `-0.015em ~ -0.025em`，600/700。
   - Source Sans 3：正文、表格、节点名。
   - Source Serif 4 *斜体*：“讲解者的声音”。用于导语、图里的旁注、图例释义、封面副标题。
   - JetBrains Mono：标签（**全大写 + 0.18em 字距**）、章节号、`FIG. 1.3`、代码、标识符、页脚、引用出处。
3. **每张图只证明一件事。** 图注第一句加粗，就是这个结论；后面用灰色补充画了什么、数据从哪里来。附录的图表索引也按结论列。
4. **有出处。** 正文里随手标出处（`spec §1, invariant 4` 用灰色小号等宽字），交叉引用写成“提交机制 (p. 29)”，每节末尾用 `Sources:` 列出依据的文件。如果演示的是真实运行，就用真实数据，例如步骤号用真实的 commit 序号。
5. **克制。** 暖纸底 `#FBF9F5`、蓝黑墨色 `#1C2633`（不用纯黑）、1px 细线、2px 圆角。**不用**阴影、渐变、大圆角卡片、emoji 图标、高饱和色块。层级靠字体、字距和细线建立，不靠颜色和体积。

## 颜色

中性色：`--paper` 页面、`--panel` 图版底、`--well` 代码块和引用框、`--rule` / `--rule-strong` / `--rule-soft` 三档细线、`--ink` / `--ink-2` / `--muted` / `--faint` 四档文字。

语义色有三档：`--x` 用于描边、文字、标签；`--x-line` 用于节点边框；`--x-tint` 用于节点填充。

| token | 通用含义 | 原书含义 |
|---|---|---|
| `blue` #35739A | 主要数据、记录、主体对象 | 对话、条目 |
| `aqua` #04828C | 持久化、提交、存储、真相来源 | Session、commit |
| `violet` #6F5F9D | 队列、等待处理的输入 | 提交、收件箱 |
| `green` #007C61 | 文档、同步 / 共享状态 | 文档、Chord |
| `amber` #9C6C1E | 工作单元、任务、阶段、检查点；也是品牌色 | 任务 |
| `plum` #8D5B87 | AI 模型、生成 | 模型 |
| `forest` #3B6B56 | 外部世界：工具、网络、副作用 | 工具 |
| `indigo` #4D64A6 | 观察者、视图、事件、订阅 | watch |
| `rose` #A9556D | **只表示失败** | 崩溃、中止 |
| `grey` #727A85 | 宿主或外部参与者、不活跃、范围外 | 宿主程序 |

把新领域映射到这张表时，按“它是什么种类”来对应，不要按名字对应。超过 10 种含义，说明图要表达的东西太多了，应该拆开。

**章节强调色**：在 section 上加 `data-accent="amber"` 这类属性，会同时改变这一章的章节号、图版左侧色条、图标题和要点框顶线的颜色。每一部分固定使用一种颜色。

## 页面结构

```
页眉：小节名（左） · 产品名（右）                     ← .tm-runhead
3.2                                                   ← .tm-num  等宽，章节色
一次渲染的生命周期                                     ← h1  Manrope 600
从快照到像素：每一帧都来自同一份已提交状态。            ← .tm-dek  衬线斜体，灰，≤2 行
────────────────────────────────────────────────      ← 细线
正文 … h2 … 正文 … 图版 … 图注 … 表格 …
┌ 对你意味着什么 ┐                                      ← .tm-takeaways  3–5 条祈使句
Sources: file (field); file §2 …                       ← .tm-sources
页脚：PRODUCT / TECHNICAL MANUAL                 70   ← .tm-runfoot
```

- **封面** `.tm-cover`：方格纸底纹；左上 Logo（琥珀色方块），右上是版本铭牌（`.tm-plate`：等宽、0.28em 宽字距）；一条 `PLATE I · …` 横栏；一张信息量很大的主图版，配编号图例 `.tm-key`；底部是大标题，加一行琥珀色衬线斜体副标题，再加一排语义色圆点 `.tm-dots`。
- **部分扉页** `.tm-part`：整页深海军蓝 `#102032`，依次是 `PART 5` 等宽标签、大标题、斜体导语、一条短强调线接长细线、本部分小目录；右下角是巨大的半透明章节号 `.tm-ghost`，颜色带一点本部分的强调色。
- 正文宽度控制在 `--measure`（72ch，中文约 35 字），图版可以更宽，最宽到 `--page-max`。

## 图表

画图前先读 `references/figures.md`。要点如下：
- 图版有 3px 章节色左条，表头是 `FIG. n.m` 加标题，右上角标出图的类型（FLOW / SEQUENCE / STATE / DECISION / STRUCTURE）。
- 8 种箭头：调用 = 实线 ink；提交 = 实线 aqua；只改状态 = 虚线 amber；模型请求 = 实线 plum；外部效应 = 虚线 forest；事件 = 点线 indigo；失败 = 虚线 rose；回复 = 虚线 aqua。图要讲的那条箭头加粗。
- 箭头标签用等宽字，颜色跟箭头一致；箭头下方用灰色小字说明；图里的旁注用衬线斜体。
- 虚线框表示待定或推断出来的；斜线填充表示等待中或在范围外；玫瑰色锯齿线表示崩溃。
- 优先用内联 SVG，颜色引用 CSS 变量，深色模式就会自动跟上。

## 文字口吻

这套风格一半在文字。照着写：
- **标题就是结论或问题**：写“一个阶段如果什么都没提交，就会永远重跑”，不写“阶段说明”。
- **导语一句话**，说清这一节回答什么，或者读完能做什么。
- **术语第一次出现时加粗并下定义**，之后全文用词保持一致。
- **要点框写 3–5 条祈使句**，读者照着做就行。
- 标识符、数字、路径一律用等宽字；不确定的地方直接说“推断出来的，日志里没有”。

## 适配其他载体

- **应用 UI 或面板**：用 tokens；面板标题用 `.tm-label` 风格（等宽大写宽字距）；状态色严格按语义（错误用 rose，运行中用 amber，已保存用 aqua）；分组靠细线和留白，不用卡片阴影。
- **幻灯片**：每页一张图版加一句加粗结论；封面用方格纸底纹；部分分隔页用深色扉页和大号半透明数字。
- **Mermaid / 其他图表库**：把主题变量映射到这套 token，箭头样式尽量对应那 8 种语法；做不到的就改用 SVG。
