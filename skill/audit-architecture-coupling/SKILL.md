# MIT/Suh 公理设计：架构体检、拆解改造与重构复核

从功能契约与控制因果出发，把架构耦合识别、方案拆解、分波施工、效果复核与收口判断串成一条按需止步的闭环。只读分析或方案任务在对应阶段交付并停止；使用本技能不自动授予修改业务代码或发布上线的权限。

## 核心判据（贯穿全程）

- **FR 与 DP 口径**：**FR（功能需求）**来自用户功能、协议契约或可观察不变量；**DP（设计参数）**是承担该责任的主要机制、状态或接口。不把文件名或目录名直接当作 FR/DP，对照前后保持同一 FR 口径与 DP 映射。允许按真实先后关系重排行列得到下三角，但须保留原映射与依赖关系，不能把重排或合并分组说成依赖已消失。
- **第一公理（独立性）**：改变某个 DP 时，其他 FR 能否独立满足？定性矩阵区分三类形态：**对角阵（uncoupled，互不影响）**、**可正确定序的下三角阵（decoupled，单向可按序满足）**、**不可仅靠排序消除的双向/强连通块（coupled）**。定性矩阵不是数值 Jacobian；**正常的显式数据输入导致预期输出变化，不判为耦合缺陷**。
- **第二公理（信息量 $I = -\log_2 P$）**：只在明确“成功范围”且拥有有代表性的成功概率数据时量化比较复杂度或可靠性；无真实样本不编造数字。测试通过率、代码行数、文件数或模块数都不是概率 $P$。
- **三类证据分开记账**：
  1. **实现依赖图**：区分值导入（影响运行期加载与模块环）与纯类型导入（如 `import type`，运行期擦除）及可达依赖扇出；零环 `import` 不等于运行时解耦。
  2. **责任与时序耦合**：追踪状态所有权、可写端口（含 `readonly` 外壳下暴露的可变对象或代理委派）、控制回调与 `await`/取消/退出路径；回调本身不判坏，重在谁改谁的状态、谁决定终止。
  3. **外部协议必需反馈**：由外部客户端、阻塞钩子或宿主事件循环决定的物理闭环（如请求 → 工具执行 → 结果回传）。此类闭环无法靠挪文件消灭，合理目标是将其收敛进单一清晰的协作块或状态机边界，并如实标注块内保留的耦合。

## 端到端闭环（按需止步）

每步写明 `输入 → 动作/判断 → 产出或停止点`；仅需分析或方案时在相应阶段收口，后续阶段为条件分支。

### 1. 定标与盘底
- **输入**：用户诉求、目标对象/版本或 commit、设计契约与行为不变量、工作区既有能力与测试夹具。
- **动作/判断**：提炼可观察 FR 与必须保留的不变量；盘点既有依赖分析器、测试与真实运行入口；明确本轮授权边界（只读分析 / 方案设计 / 实施改造 / 交付上线）。
- **产出或停止点**：FR 与不变量清单、对象版本身份、既有验证基线与授权边界；仅暂停缺授权的动作。影响路线且工具无法查明的目标取舍交用户确认，其余明确工作继续。

### 2. 源码耦合取证与当前矩阵
- **输入**：FR 清单、插件或模块的真实入口（不凭静态依赖图单独定论）。
- **动作/判断**：从真实入口通读源码，映射当前 DP 与状态归属（文件/进程/通道/等待时序），构建当前 FR/DP 矩阵并区分**正常显式数据输入**、**内部耦合**、**外部约束**及**混合耦合**。重点排查五类高发接缝：①共享可变状态与多写者；②跨模块反向驱动终态或取消；③历史/原件再解释（二次投影或重读可变源）；④observer 在启动/交接/关闭上 `await` 拖延执行；⑤取消、关闭与恢复路径不对称或遗留临时回执。所有实质 finding 绑定 `file:line:symbol`（或原始轨迹）与可观察影响，分开标注**事实 / 推断 / 未知**；静态无法区分最像的竞争解释时，在授权内用最小探针实测。
- **产出或停止点**：当前 FR/DP 矩阵与带归因的耦合账本。**若任务仅要求架构体检或只读评估，在此交付并停止。**

### 3. 目标设计与 ROI 权衡
- **输入**：当前 FR/DP 矩阵、耦合账本、外部约束边界。
- **动作/判断**：按第一、第二公理设计目标分层与私有状态唯一归属：将外部必需闭环与敏感异步清理收敛到清晰的端口与**联合生命周期事务**，其余纯规划、编解码、账本与只读观察单向分层。不预设必须使用纯 reducer、事件总线、零回调或拆出更多小文件；对比拆分收益（缺陷关闭、未来变更传播缩窄）与维护代价（胶水端口、跨层跳转、时序风险），并将可能改变可观察行为的疑似缺陷单独标出供决策。
- **产出或停止点**：目标 FR/DP 矩阵、私有状态归属与端口契约表、待裁决行为修正清单。**若只出架构方案且无需施工编排，可在此交付。**

### 4. 分波改造方案与回退边界
- **输入**：目标设计、依赖顺序、高风险回归面（如测试直接读内部成员、多处路径公式）。
- **动作/判断**：按依赖与风险拆成可独立验证的波次——一般建议**先共享契约与纯函数，再独立有状态服务，再联合执行核心与宿主边界**，但依实际耦合形状和风险调整波次，不机械照搬固定波数。每波写清：前置输入、允许改动范围、必须保留的契约、受影响相邻消费者与退出路径、定向验证方式，以及可回退点（如兼容门面）。
- **产出或停止点**：分波计划表。**若任务只需拆解方案与排期，在此交付并停止。**

### 5. 分波实施、回归与缺陷分账（需实施授权）
- **输入**：分波方案、既有验证基线与实施授权。
- **动作/判断**：按波迁移并验证受影响消费路径与退出/释放路径；对第 2/3 步发现的疑似缺陷逐行核实或跑最小反例——**已确认的功能违约应在授权内修复，不借“保持现有行为”留下真缺陷**，并在记录中把**纯结构重构**与**行为缺陷修复**明确分账。外部独立复核或流程门禁按项目实际需要选用，不作为本技能通用前置。
- **产出或停止点**：已落地的结构改造、行为修复清单、分账记录与离线回归/类型检查证据。

### 6. 同口径前后复核
- **输入**：改造前基线源码/矩阵、改造后候选、已有测试与依赖分析记录（优先复用未受变化影响且源码身份一致的证据，不为体检默认重跑无关全套或联网）。
- **动作/判断**：沿用原 FR 编号与 DP 职责口径；合并、拆分或重编号时列出 `原项 → 改后项` 映射。围绕支撑主要结论的耦合变化，写清谁改谁状态或谁决定终止、改前 → 改后的实际关系、源码或实测轨迹、仍保留的控制关系，并按 **达成 / 部分达成 / 必要耦合保留 / 待验证（附原因）** 归类。将内部协作与外部必需反馈分账，后者注明具体协议、阻塞钩子或宿主条件。分别核对三类耦合变化与**四维收益/代价**：①具体缺陷关闭（区分功能修复与结构梳理）；②未来变更传播范围；③代表性实测结果与成立条件；④模块数、总行数与跨层接口维护代价。按证据覆盖的关系与场景写结论。
  - **正例**：将外部阻塞反馈收敛到单一生命周期事务边界，单独记明内部观察器经注入回调触发续接的控制关系；因主要缺陷已闭环、现有回归覆盖该边界且继续细拆需重碰异步停止时序，建议停止深拆。
  - **反例**：把多条协作合并成一格并标成外部必要闭环，据此宣称原依赖已清零——这只改了画法，没有证明依赖消失。
- **产出或停止点**：FR/DP 映射（有调整时）与前后矩阵、主要耦合变化的责任/证据对照、四维收益代价账本及未覆盖缺口。

### 7. 收口或继续裁决
- **输入**：前后复核结论、剩余耦合风险、当前业务需求与实测覆盖情况。
- **动作/判断**：
  - **建议收口（停止继续深拆）**：关键边界与入口已清晰、已确认的功能缺陷已闭环、剩余耦合局限在局部契约端口或单一生命周期事务内且已有对应的功能回归测试与运行证据兜底，同时当前没有受阻的新需求或实发故障——对照下一刀能关闭的具体问题与新增接口/重碰敏感时序成本，收益不足时不继续深拆。
  - **应当继续或修复**：仍存在已证实的功能违约或持续引起回归的跨界写状态时，在授权内继续处理，不用“整体收益小”掩盖缺陷。
- **产出或停止点**：裁决及依据、继续拆分的具体收益与成本、值得重启改造的需求或故障条件，以及未覆盖边界与证据缺口。**若任务不含发布上线，在此交付并停止。**

### 8. 真实宿主验收与按授权交付（条件分支，需交付授权）
- **输入**：收口确认的候选版本、受影响的真实宿主/消费面清单、发布与重载授权。
- **动作/判断**：静态图改善不等于运行时独立或已激活；按当前风险补充受影响真实宿主消费路径及在途取消、关闭与资源释放验证（按目标对象风险选最小充分路径，不把特定项目的实跑请求数或命令写成通用必做）。冻结候选，确认源码身份、打包产物、激活入口与真实加载实例可追溯到同一受审内容（按构建/安装映射核对，不要求源码与编译产物逐字节相同）；按项目授权流程发布、资源重载或验证回滚，并保存原始证据。
- **产出或停止点**：源码/候选/激活/加载一致性证据、宿主验收记录与可回滚入口。
